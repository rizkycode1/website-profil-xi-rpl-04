JAWABAN PERTANYAAN

Pertanyaan: Apa arti hasil git status?
git status digunakan untuk melihat kondisi repository saat ini, seperti branch yang sedang aktif, perubahan file, dan file yang belum di-commit.

Pertanyaan: Mengapa setiap developer tidak langsung bekerja pada main?
Agar setiap developer dapat mengerjakan fitur secara terpisah tanpa mengganggu branch main. Dengan branch, perubahan dapat diperiksa terlebih dahulu sebelum digabungkan ke main.

Pertanyaan: Apa perbedaan pesan commit update dengan Menambahkan halaman profil? Mana yang lebih baik?
update terlalu umum sehingga tidak menjelaskan perubahan yang dilakukan. Sedangkan Menambahkan halaman profil lebih jelas karena menjelaskan isi perubahan. Jadi, Menambahkan halaman profil lebih baik.

1. Apa fungsi git pull?
. git pull berfungsi mengambil perubahan terbaru dari repository remote GitHub dan menggabungkannya ke repository lokal.

3. Apa yang terjadi jika programmer tidak melakukan git pull?
Programmer bisa menggunakan kode yang sudah tidak terbaru sehingga perubahan dari anggota lain belum tersedia di repository lokal dan dapat menyebabkan masalah saat melakukan kolaborasi.

5. Mengapa main harus dijaga agar tetap stabil?
   Karena main merupakan branch utama yang berisi hasil pengembangan yang sudah diperiksa dan digabungkan. Menjaga main tetap stabil mencegah kode yang bermasalah mengganggu hasil proyek.

   1. Mengapa conflict terjadi?
   Conflict terjadi ketika dua developer mengubah bagian yang sama pada sebuah file dan Git tidak dapat menentukan perubahan mana yang harus digunakan

2. Apakah conflict berarti Git rusak?
   Tidak. Conflict merupakan hal yang normal dalam pengembangan perangkat lunak ketika terjadi perubahan yang bertabrakan.

   3. Siapa yang harus menentukan versi kode yang benar?
      Developer yang bertanggung jawab terhadap kode tersebut bersama anggota tim yang terkait harus menentukan versi yang benar berdasarkan kebutuhan proyek.

      4. Mengapa komunikasi antar programmer penting?
      Karena komunikasi membantu anggota tim memahami perubahan yang dilakukan, menghindari pekerjaan yang bertabrakan, dan menyelesaikan conflict dengan benar.

REFLEKSI INDIVIDU
1. Apa perbedaan bekerja sendiri dengan bekerja menggunakan Git dan GitHub?
   Bekerja sendiri lebih sederhana karena hanya satu orang yang mengelola kode. Dengan Git dan GitHub, beberapa programmer dapat bekerja bersama menggunakan branch, commit, Pull Request, Code Review, dan merge.

   2. Apa manfaat branch?
Branch memungkinkan developer mengerjakan fitur secara terpisah tanpa mengganggu main.

3. Mengapa Pull Request diperlukan?
Pull Request diperlukan agar perubahan kode dapat diperiksa dan direview sebelum digabungkan ke main.

4. Apa manfaat Code Review?
Code Review membantu menemukan kesalahan, memeriksa kualitas kode, dan memastikan perubahan sesuai dengan kebutuhan proyek.

5. Error apa yang paling sulit kalian selesaikan?
Error saat melakukan git push karena terdapat perubahan yang belum tersinkronisasi dengan repository GitHub.

6. Bagaimana kalian menemukan solusinya?
Saya membaca pesan error, mencari penyebabnya, berdiskusi dengan anggota kelompok, kemudian mencoba solusi yang sesuai.

7. Apa kontribusi terbesar kalian dalam kelompok?
Kontribusi terbesar saya adalah mengatur repository, membagi tugas anggota, memeriksa Pull Request, melakukan Code Review, dan melakukan merge.

8. Jika menjadi programmer profesional, kebiasaan apa dari kegiatan ini yang akan kalian pertahankan?
Saya akan mempertahankan kebiasaan menggunakan branch, membuat commit dengan pesan yang jelas, melakukan Code Review, berkomunikasi dengan tim, dan menjaga branch main tetap stabil.
